# Search and loading configuration

The build writes readable English HTML for `/`, `/c/hottest`, `/c/realtime` and `/c/updated`, plus a personal `/c/focus` document and a 404 page. Each public page includes its own title, description, H1, navigation and source directory before JavaScript runs. Live third-party headlines remain client-loaded; this is not full server rendering of recommendation feeds. The same initial HTML is served to people and crawlers.

Set `SITE_URL=https://your-real-domain.example` in the build environment (or the ignored `.env.server` file), then rebuild. Use the actual public origin, without a subdirectory. Until configured, the build omits canonical URLs, absolute social images, structured data and sitemap.xml. It never substitutes a template owner's domain or guesses the deployment hostname.

With `SITE_URL` configured, the build generates CollectionPage/WebSite structured data and sitemap.xml, and adds the sitemap URL to robots.txt. `/c/hottest` canonicalizes to `/` because both represent the same public feed. The sitemap includes `/`, `/c/realtime` and `/c/updated`; personal following and missing pages use `noindex, follow`. No invented publication dates, ratings or full-platform rankings are included.

Serve the generated HTML files on their matching paths. The Node preview also returns HTTP 404 for unknown routes. Keep the generated `404.html` when deploying to static hosting. The build produces Brotli and gzip versions of static assets, and the Node server negotiates compression. Hashed assets may be cached for a year; HTML and service-worker files must revalidate. API data retains its existing source-specific cache and refresh rules.

The JavaScript build targets Safari/iOS 16.4 and newer, alongside modern Chrome, Edge and Firefox. It uses native image lazy loading and IntersectionObserver with a fallback, dynamic viewport height with a `vh` fallback, safe-area insets, touch targets, reduced-motion preferences and Safari-compatible dialog positioning. iPhone/iPad installation uses Safari's Add to Home Screen; Mac installation includes Add to Dock for macOS Sonoma and newer. These compatibility changes require verification on real Apple hardware before claiming device certification.

Before publication, run `npm run typecheck`, `npm run lint`, `npm test -- --run` and `npm run build`. Start the production preview, then run `npm run check:seo -- http://127.0.0.1:4173` to verify real HTTP statuses, route metadata, headings and asset caching. Inspect 320px/390px/tablet/desktop layouts, and verify source search, following, sharing, installation help and language switching. After deploying on the real domain, submit its sitemap in Google Search Console and measure real-user Core Web Vitals; a local build does not establish search rankings.
